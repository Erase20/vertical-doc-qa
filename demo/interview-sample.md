# 星云知识库管理系统

## 产品定位

星云知识库管理系统面向企业内部的垂直文档问答场景。用户可以把产品手册、
制度文件和项目资料上传到系统，通过自然语言问题检索资料，并查看回答所使用
的原始文档片段。

## 技术架构

系统前端使用 Next.js，后端接口使用 FastAPI。文档解析、文本切片和向量生成
由 Celery Worker 异步执行，任务消息通过 Redis 传递。文档元数据、会话信息和
文本向量统一存储在 PostgreSQL 中，向量检索由 pgvector 完成。

## 文档处理流程

用户上传文档后，系统首先保存原文件并计算 SHA-256 摘要，用于避免同一知识库
中重复保存相同内容。随后文档依次进入 parsing、chunking 和 embedding 状态。
系统支持 PDF、DOCX 和 Markdown 三种文档格式，会将正文切分为便于检索的
文本块，再生成向量并写入数据库。文档上传后依次进入 uploaded、parsing、
chunking、embedding 和 ready 状态，处理失败时状态为 failed。

## 问答流程

用户提问时，系统先生成问题向量，然后使用余弦相似度检索最相关的文本块。
默认检索 Top 5 结果，并过滤相似度低于 0.25 的内容。检索结果会按 S1、S2、
S3 的顺序编号，作为 Prompt 上下文发送给大模型。模型回答中的 [S1] 表示该
结论来自第一个来源片段。

## 流式输出

问答接口使用 Server-Sent Events 流式返回结果。前端依次接收 meta、sources、
token、usage 和 done 事件。meta 事件包含请求编号，sources 事件包含引用来源，
token 事件用于逐字展示模型回答，usage 事件记录输入和输出 Token。

## 数据隔离

文档、文本块和会话都包含 knowledge_base_id 字段。不同知识库的数据通过该
字段隔离。当前演示版本默认使用 default 知识库，后续可以扩展为多个独立部门
或项目知识库。

## 当前限制

当前版本没有用户登录和权限管理。API Key 也没有用于接口鉴权。正式公开服务
之前，需要增加身份认证、访问控制、限流和敏感信息审计。系统还会保存检索
事件和模型调用记录，用于分析检索质量与 Token 成本。
